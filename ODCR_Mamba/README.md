# ODCR-Mamba

Optical-depth-conditioned state propagation and dual reconstruction for single-image dehazing.

本目录提供固定 ODCR-Mamba 模型的推理代码、模型权重、关键实验数据及可追溯记录。代码对应单张有雾 RGB 图像输入、光学深度条件四方向状态传播、直接重建与物理重建融合的网络。结果对应内部稿件 V100（2026-10-01），不表示论文已经发表或通过同行评审。

## 包含内容

| 路径 | 内容 |
| --- | --- |
| `src/odcr_mamba/` | 固定模型、状态扫描、重建损失和训练验证指标源码 |
| `infer.py` | 单张图像推理，保存新 PNG，不覆盖已有文件 |
| `weights/` | 仅模型张量，不含优化器状态及本地配置 |
| `configs/` | 固定结构参数、选定权重的训练参数摘要 |
| `results/main_tables/` | 主文 Table I–VIII 的显示值与未舍入值 |
| `results/per_image/` | 自然场景、SOTS、RRSHID 的逐图测量记录 |
| `provenance/` | 来源哈希、模型身份、代码一致性验证 |
| `FILE_SHA256_2026100109.json` | 发布文件 SHA-256；不包含自身 |

原始数据集、原始/处理后图像、其他方法的代码和权重、私人路径、论文文档及历史模型均未收录。本包未附完整训练执行器和训练数据预处理流程，不能视为从原始数据重新训练的完整复现包。

## 快速使用

进入 `ODCR_Mamba` 目录，在独立 Python 环境中安装依赖：

```bash
python -m pip install -r requirements.txt
python -B verify_release.py
python -B infer.py --input your_hazy_image.png --output outputs/restored.png --device cpu
```

具备兼容 CUDA 环境时可将 `--device cpu` 改为 `--device cuda`。未使用 `mamba-ssm` 或自定义 CUDA 扩展。参考验证环境为 Python 3.8.20、PyTorch 1.10.0、NumPy 1.24.4、Pillow 9.4.0；其他版本及 GPU 平台可能存在浮点差异，本次仅验证了 CPU 发布封装的一致性。

输入按 RGB 解码，转为 `[0,1]` 的 float32；两边均需至少 16 像素。保持原始尺寸，不做自动裁剪、缩放、分块或测试时增强。推理使用 `eval()` 与 `no_grad()`，不启用混合精度。高分辨率图像需要较多内存；本程序不会为规避内存不足而自动改变推理协议。PNG 像素按截断范围、乘 255、四舍六入五成双（`np.rint`）转换为 uint8。PNG 编码器不同可能导致文件字节不同，因此不能用不同编码器生成的 PNG 文件哈希直接判定像素不同。

## 固定模型身份

- 网络类：`StandaloneODCRMamba`；参数量：2,042,064；权重张量：476。
- 选定 checkpoint 步数：60,000。所有本文方法的主输出数据均指向此固定模型。
- 原始完整 checkpoint SHA-256：`D696BBFA42DD1A840708B9C42E824036862ED17D538B2B47551641D8145854DB`。
- 本包模型张量文件 SHA-256：`7F9474B9AE6D42287EB72AE5F750AA284824EE67D14538F2C6F01DDC4F695FC2`。

两个文件哈希不同是因为移除了优化器等非模型内容；导出的全部 476 个张量与原始 checkpoint 逐元素完全一致。推理脚本在反序列化前校验本包权重哈希。请勿替换为来源不明的 `.pt` 文件。哈希校验用于完整性检查，不等于发布者数字签名。

代码只做依赖整理：保留实际使用的模块，移除未使用原型，修改模块导入位置。原版与发布版在两种尺寸的合成张量输入上输出完全相同；这些检查不是新增数据集实验或性能测试。配置中的学习率计划长度不代表已经完成相应长度的训练。

## 实验数据及使用边界

| 数据 | 发布记录量 | 说明 |
| --- | ---: | --- |
| 主文表格 | 8 张 | 显示数据与 V100 文稿的三位小数逐项一致 |
| 本文方法自然场景 | 185 行 | 四个数据子集；不是额外的 185 个训练样本 |
| SOTS 室内/室外对比子集 | 4,400 行 | 11 种方法 × 各 200 对图像；本文方法 400 行另存为方便检索的子集，不能重复计数 |
| SOTS 本文方法完整归档 | 1,000 行 | 主表 V 对应室内、室外各 500 对；包含上述本文方法 400 行，不是额外独立样本 |
| RRSHID-Test | 304 行 | 本文方法最终融合输出 |
| RRSHID 分支 | 912 行 | 同一 304 对图像的三个分支；包含融合输出，不能与 304 行相加当作独立样本 |

请先阅读 `PROVENANCE_RESULTS.json` 和 `results/RESULTS_SCHEMA_2026100109.json`。各导出文件的来源及适用范围均有记录。显示 CSV 保留论文显示值；未舍入值及归档标量重聚合值见对应 JSON；未通过四舍五入反推精确值。导出只重排已有证据并核对表格，没有重新计算图像指标，也没有虚构缺失值。

重要区别：

- 主表 III 来自已核对的归档记录，**不整体宣称通过 strict-v12 完整验收**。历史归档结果与更严格结果合同的状态已分别保留，不混为一类。
- RRSHID 与自然场景/SOTS 的 SSIM 窗口协议不同，分别为 Uniform11 与 Gaussian11。`training_metrics.py` 是训练验证用的指标实现，不能代替所有表格的正式评估程序。LPIPS、DISTS 及完整历史评测环境未打包。
- 发布的 SOTS 对比 CSV 使用室内、室外各 200 对图像，不是完整测试集排名；主表 V 为同一固定模型在室内、室外各 500 对图像上的历史归档结果，1000 行逐图记录另存。本文方法 400 行是这 1000 行的严格子集。外部方法训练数据与测试数据的全部交叠关系尚未完全核实，不据此宣称所有标准基准上的领先性能。
- 分支记录是同一固定模型内部的直接重建、物理重建和融合输出，**不是移除模块后重新训练的消融实验**。
- SIFT 为等权数据集平均；GMAE/RGBMAE 表中使用乘 1,000 的显示尺度。GMAE 在 RGB `[0,1]` 上计算水平、垂直一阶差分误差的绝对均值，再对两个方向等权平均；RGBMAE 为全图 RGB 绝对误差均值。详见各表元数据，不把不同加权方式或尺度混算。

归档证据中的项目相对路径用于追溯原始研究目录，不表示相应原始文件全部包含在本 GitHub 子目录内。原始数据请依照各数据集和方法作者的许可自行获取。数据与各表来源见 `PROVENANCE_RESULTS.json` 和相应表格元数据。
